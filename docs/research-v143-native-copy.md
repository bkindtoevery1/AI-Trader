## Reason And Scope

Each branch retains decision snapshots containing public accounting history.
Subsequent daily transaction copies include those accumulated observations.
Snapshots exclude observations themselves, so this is repeated history
amplification, not recursive self-embedding. The fourth anchor required roughly
301-372million dictionary copies per cell despite the qualified Python adapter.
The fixed ten-session horizon, all states and mutable detachment remain intact.

Only the private exact-list/dict copy loops move into a small C extension.
Every non-atomic child still calls the original private Python copier with the
same memo; reconstruction, tuple/method handling and keep-alive stay original.
New native containers preserve atomic identities, alias/cycle topology and
value-before-key callback order. Real iterators preserve mutation behavior.
No shared mutable histories, persistent memo, pickle replacement, recursive C
deepcopy engine, global copy-registry patch or scientific change is introduced.

The C API follows Python's [iterator contract](https://docs.python.org/3.14/c-api/iter.html),
[exact dictionary and reference rules](https://docs.python.org/3.14/c-api/dict.html)
and [reference ownership rules](https://docs.python.org/3.14/c-api/refcounting.html).
Local CPython3.14.3 copy.py remains the actual behavioral reference. Native
qualification is limited to GIL-enabled macOS arm64 with those exact headers.

The adapter requires explicit loading of an already compiled binary and a
caller-supplied hash. It never compiles or activates automatically. Loaded
namespace/platform checks are not filesystem reauthentication or hostile
concurrent-replacement protection. Binary/source provenance and any later
market admission belong to a separate caller. No universal equivalence is
claimed for allocator-failure timing, frame/refcount introspection, concurrent
mutation or identical recursion cutoffs. Existing native finite trace depths
remain the intended domain; no existing guard has been relaxed.
