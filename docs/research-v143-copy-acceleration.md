## Narrow Change

The optional component is tools/nq_apex_continuation_copy_acceleration_v143.py.
It reuses the repository's existing immutable-window proof helpers. No frozen
module, class method, runner or global is patched. Private forwarding views
route only direct population/fork copy sites through a call-scoped memo.
TransitionAccount.process_day retains its original copies and all JSON/history
serialization. The tick kernel, teacher calls, callback order, hashes, account
lifecycle and target construction remain original.

Every miss executes the original complete copy and validation. Only exact
native metadata and recursively immutable integer tick tuples may obtain a
proof. Strong references to every bound value prevent identity reuse; a hit
requires exact identity of all values, not a content-hash coincidence. A hit
returns a new native window shell sharing proven immutable rows. It never
shares mutable account histories, predictions, output dictionaries or lists.

Rebinding, malformed inputs, subclasses, instance overrides and observed copy/
validator/date/record runtime drift cannot reuse a proof. Live original code
handles fallback cases. The memo retains at most64 bindings, evicts least
recently used bindings and clears on exit including exceptions. This is a
binding-count bound, not a byte-memory guarantee. The original8GiB process
high-water guard remains required for any later real-data use.

Entry-point proofs and shallow namespace/function checks are rechecked before
returning an accelerated result. Tracked mid-call runtime drift fails closed.
These checks do not authenticate imports or arbitrary transitive mutable
dependency state; source, teacher, runtime and complete-tape authentication
remain the runner's responsibility. Inputs are not an atomic concurrent
snapshot, matching the original constraint.

## Test Evidence And Decision

The final combined affected run passed1010 unique tests in39.097 seconds,
actual exit0/session87016, zero failures/errors/skips. It includes121 adapter
and7 dense-fixture tests; do not add earlier overlapping agent/smoke passes.
Coverage includes all four modes, both roll-ins/continuation arms/phases,

A fresh whole-repository run stopped at the configured third failure:
1179 passed,3 failed,1 skipped in80.018 seconds; actual exit1/session23167.
The three causes match the previously documented V144 limitations: isolated
deployment-loader manifest mismatch, pre-existing dirty broker.py versus the

in pre-turn HEAD dafaa7e7). No unrelated code, evidence hash or ledger field was
changed to force green. This is not a whole-repository pass or a model pass.

Decision: retain the tested optional component, but do not adopt it in the
market collector or start another batch. The measured gain is limited and
leaves account/history copying untouched. Next investigate that larger cost
while preserving aliasing, detachment, rollback, callback guards and exact
complete output hashes. Actual first-cell equivalence/resource proof and a
reviewed continuation remain prerequisites for integration. Do not shorten the
horizon, omit states or weaken economic gates for speed.
