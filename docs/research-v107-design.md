This is one outcome-informed execution-policy candidate using existing causal
V102 models, not a newly trained estimator or independent validation. V106
remains closed and the comparison ledger stays 13,175 until a separate valid

## Hypothesis And Prior Failures

V105's NQ arms shared early PA losses and then many zero-capacity skips. V106's
concave target instead eliminated all PA nominations. Neither result supports
loosening real account limits or forcing positive predictions.

Test a fixed phase switch: retain original NQ Evaluation, then use the original
MNQ model and actual MNQ tape from the first PA date. This can reduce initial
PA dollar exposure before losses deplete capacity, but also reduces gross
dollar profits and incurs different costs. It may still abstain, lose money,
miss activity requirements or fail payout. Smaller contracts are not an edge.

V98 already tested a different shared-account product router and failed. That
router ranked current capacity-adjusted forecasts at each decision in both
phases. V107 has no such ranking, drawdown trigger, fallback quote or per-trade
product reselection. Its route is fixed by the account phase before quotes.
It also uses V102's original causal models, not V98's V97 models. This is a
bundled product-and-forecast policy effect, not an isolated quantity effect.

## Exactly Two Arms

A is the exact completed V105 gate-only NQ account in all four modes. C keeps
A's Evaluation unchanged, then substitutes the original MNQ forecasts and
MNQ execution for PA. Both retain the PA stop<=140 nomination mask and nominal
stop<=5*target entry guard. Do not broaden MNQ support, change thresholds or
rescale NQ forecasts into MNQ forecasts after seeing results.

Require complete ordered forecasts for both products, original source event
identities, own initial reference exposures, and explicit same-maturity tapes.
Both product input sets are validated, but only the predetermined product can
request a future entry window. A failed MNQ geometry or a negative MNQ forecast
cannot trigger an NQ rescue trade. A malformed unused input aborts the day;
it does not become a profitable selective exclusion.

The original begin_day owns every transition. In particular, pending PA starts
on the next processed date with a fresh research PA balance; Evaluation profit
is not carried into that separate account. Keep all original Evaluation
history, resets, billing, PA cash, floor, day-start MAE, prior-day plan unlock,
activity calendar, hypothetical payout and actual-exit cooldown. No extra
phase reset is allowed when the product changes. Daily rows own their actual
product; the report labels its mixed-phase route explicitly.

Retain half-headroom sizing, NQ<=1, MNQ<=6 and any stricter current plan ceiling.
The implemented fresh PA plan permits only five MNQ until prior-day unlock,
not six automatically. These describe the frozen research account, not newly
verified official rules. Costs, slippage, latency, tick first-touch, adverse
path, original targets, uncapped trade count and five-minute cooldown remain.
