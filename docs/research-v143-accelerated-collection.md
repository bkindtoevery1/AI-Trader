## Implementation

The reusable entry point is tools/run_nq_apex_continuation_accelerated_v143.py.
It imports all seven original recovery files as independent exact-byte copies
in a new private continuation root. It preserves the original claim and cell
chain; the old interruption, recovery and equality-probe roots are unchanged.
The imported completion.json certifies only the original first cell. New batch
and run receipts determine subsequent progress.

Original collect bytecode, prefix semantic checks, raw/window receipts,
first-fold teachers and all256 cells remain unchanged. A private function clone
replaces only the population call with the qualified copy adapter and adds
publication memory checks. No model, frozen global or source file is patched.
Qualification binds the current adapter/proof sources to the actual first-cell
receipt, not merely a newly calculated source hash. The explicit integration
inventory extends, rather than replaces, all250 original source dependencies.

The central resume cursor separately pins cell/batch counts, tail cell,
integration and external terminal hashes. The child never advances it. This
detects deletion of an otherwise consistent completed suffix, not just corrupt
individual files. Unknown artifacts, nonregular files, links, failures,
incomplete publications and missing/nonzero terminal receipts block reuse.
Run starts are exclusively claimed before source restoration. The next batch
cannot proceed merely because the child wrote its own completion JSON.

Requests are bounded to1 through8 full cells, with8GiB process high-water and
900+5,400*requested_cells seconds. This controls resource use, not scientific
population size. The first real integration invocation will append one cell;
subsequent checked batches may be larger. The end target is the original256,
not a one-cell substitute. No fitting, scoring or economic conclusion until
the unchanged complete-population/support gates allow those later stages.
